## Causa del resaltado tapando el carril

Dos capas de resaltado competían: `spring-ind` (el pill deslizante real, sistema ya existente,
`left:10px;right:10px` por defecto en `index.html` — casi todo el ancho) y mi propio
`nav.sb .ni.on{background:...!important}`, que además tiene mayor especificidad que la regla de
`index.html` que apaga el `.ni.on` estático cuando `spring-nav` está activo
(`body.spring-nav .ni.on{background:transparent}`, sin `!important`). Resultado: las dos capas se
dibujaban a la vez, ambas cubriendo el carril.

## Fix

- `spring-ind`: ahora `left:var(--nx-rail)` (antes 10px) — el pill arranca justo donde termina el
  carril, nunca lo cubre. Recoloreado a azul claro (`rgba(37,99,235,.12)`) acorde al panel blanco.
- `nav.sb .ni.on` (respaldo para cuando `spring-ind` no inicializó): en vez de un color sólido de
  fondo, un `linear-gradient` con corte duro en `var(--nx-rail)` — transparente sobre el carril,
  azul claro solo en la zona blanca. Se apaga por completo con
  `body.spring-nav nav.sb .ni.on{background-image:none!important}` para no duplicar el resaltado
  cuando el pill real ya está activo (que es el caso normal).

## Fix de centrado de íconos

Error de cálculo: el `margin-left` que había puesto no restaba el `padding-left:10px` que
`.sb-nav` sigue conservando (no lo toqué). Recalculado con el offset real de cada contenedor:
`.ni-i` (ícono, 30px) → `margin-left:9px`; `.sb-mk` (logo, 30px) → `19px`; `.sb-av` (avatar, 28px)
→ `20px`. Los tres quedan centrados en el carril de 68px.
