# 2026-09-17 03:00 — Claude — Propuesta comercial para cliente potencial (importador)

## Solicitud del dueño

El dueño pidió desarrollar una propuesta comercial para un **posible nuevo cliente**, no relacionado con el negocio de seguros: un importador de pasolas eléctricas, motos eléctricas, aires acondicionados y TV Smart. El cliente pidió un sistema que cubra: taller, página web, catálogo de mercancías y contabilidad.

## Naturaleza del trabajo

Este trabajo **no toca el código, datos ni lógica de negocio de NEXUS PRO Seguros**. Es un documento comercial/de negocio (fuera del alcance de seguros, cobros, acumulados o WhatsApp de NEXUS PRO) que se desarrolló en este repositorio porque la rama de trabajo asignada (`claude/propuesta-cliente-importador-r9peub`) vive aquí. No aplica la regla de auditoría de dinero/cobros de NEXUS PRO Seguros porque no se modificó ningún cálculo, tabla ni RPC del sistema de seguros.

## Decisiones tomadas por el dueño (vía preguntas aclaratorias)

1. **Arquitectura:** desarrollo nuevo e independiente para el cliente importador — no se reutiliza la base de código/infra de NEXUS PRO Seguros.
2. **Modelo comercial:** suscripción mensual (SaaS), con un cargo de implementación inicial.
3. **Formato de entrega:** ambos — documento Word/PDF para enviar al cliente, y versión web interactiva.

## Qué se hizo

- Se redactó una propuesta comercial completa (resumen ejecutivo, alcance por los 4 módulos solicitados, fuera de alcance, supuestos, cronograma por fases, modelo comercial SaaS con cifras orientativas, próximos pasos).

## Limitación técnica encontrada

LibreOffice (`soffice`) en este entorno no pudo convertir **ningún** `.docx` a PDF (falla también con un documento mínimo de prueba), por lo que no se pudo verificar visualmente el render del `.docx` antes de entregarlo. El archivo `.docx` es OOXML válido (generado con la librería estándar `docx`), pero el dueño debe confirmar que se ve correctamente al abrirlo en Word/Google Docs.
