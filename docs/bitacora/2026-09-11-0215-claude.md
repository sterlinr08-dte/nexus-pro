# Hora y visto a 9 px, y de paso unificados

El dueño pidió 9 px para la hora.

## Lo que había: dos tamaños distintos

La auditoría de las 36 capas mostró que la hora no tenía **un** tamaño, sino dos:

```
salientes   6.6px   capa 23 (burbuja-fit-final), 3 clases   ← ganaba
entrantes   7.7px   capa 24 (replica-referencia), 1 clase   ← ganaba
```

Seis capas escriben reglas para ese selector con tamaños entre 6.6 y 8.5 px; se aplicaban dos
distintas según el lado del chat. Eso ya era un defecto por sí solo, aunque a 6–7 px casi no se
apreciara la diferencia.

Ahora se unifican en 9 px para los dos lados.

## Tres clases, no una

Para ganarle a la capa 23 hacen falta **tres clases**. Con menos, la regla se escribe y **no se
aplica** — exactamente lo que le pasaba a la de 11.4 px del texto, que llevaba ahí sin efecto quién
sabe cuánto.

```css
#v-waInbox .nxWaBub.in  .nxWaMsgMeta,
#v-waInbox .nxWaBub.out .nxWaMsgMeta,
#v-waInbox .nxWaBub.in  .nxWaBubMeta,
#v-waInbox .nxWaBub.out .nxWaBubMeta{ font-size:9px!important }
```

## Cambio de método tras el fallo de las 02:10

Esta entrega ya **no** se valida con `node --check`, que no detectó el backtick que tumbó una capa
entera. Se valida de dos formas:

1. contando backticks e interpolaciones dentro de la plantilla CSS — deben ser **cero**;
2. **ejecutando** las 36 capas contra un DOM falso y comprobando que ninguna lanza.

Ambas pasan.
