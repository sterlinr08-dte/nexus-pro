# CRÍTICO: rompí `replica-referencia` en producción con un backtick dentro de un comentario

Corrige lo publicado en `2026-09-10-2205-claude.md`. **El error estuvo en vivo.**

## Qué pasó

El dueño mandó un reporte de error real de producción:

```
TypeError: undefined is not a function
css@parches-whatsapp-replica-referencia.js:278:66
```

Al documentar el cambio de las 12 px escribí este comentario **dentro de la plantilla CSS**:

```js
s.textContent = `
  …
  /* La capa 24 ya pedia 11.4px con `.nxWaBub` a secas … */
                                    ↑ este backtick CIERRA el template literal
```

El backtick cerró la plantilla. Lo que venía después se convirtió en un *tagged template* sobre una
expresión que no es función, y la capa entera dejó de cargar. Con ella se caen `enhanceComposer`,
`decorateBubbles` y todo el CSS de la burbuja: el chat volvía a su aspecto sin ajustar.

## Por qué no lo detecté

**`node --check` no sirve para esto.** El resultado sigue siendo sintaxis JavaScript **válida** —un
tagged template lo es—, así que pasa la comprobación sin rechistar y revienta solo al ejecutarse.
Llevo toda la sesión validando con `node --check` y dándolo por suficiente. No lo es.

## Lo hecho

1. Backticks fuera de los dos comentarios.
2. **Un aviso en el propio archivo**, justo donde empieza la plantilla, diciendo que ahí dentro no se
   pueden escribir backticks ni `${ }` ni siquiera en comentarios CSS, y que `node --check` no lo
   detecta.
3. **Una comprobación nueva que sí sirve:** ejecutar cada capa contra un DOM falso y ver si lanza. Eso
   es lo que detecta este fallo. Pasada sobre las 36 capas: ninguna revienta.

## La lección, para no repetirla

Escribir comentarios de calidad dentro de plantillas CSS es útil —lo he hecho toda la sesión— pero
**citar identificadores con backticks ahí dentro es una mina**. Dentro de una plantilla se citan con
comillas simples o sin nada. Y antes de publicar una capa hay que **ejecutarla**, no solo parsearla.
