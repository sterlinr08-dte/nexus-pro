# Corrección real de publicación — caché impedía ver el sidebar móvil nuevo

## Reporte del dueño

Después de publicar el PR #352, el dueño confirmó que en su iPhone **seguía viéndose igual** y que no aparecía el arreglo.

## Diagnóstico confirmado

El código correcto sí estaba en `main`, pero el proyecto seguía publicando:

`APP_VERSION = 58.40`

El loader `parches-seguros.js` se carga desde `index.html` con:

`parches-seguros.js?v=APP_VERSION`

Por tanto, en Safari/iPhone era posible seguir reutilizando la URL antigua
`parches-seguros.js?v=58.40` desde caché. En ese caso, el navegador ni siquiera llegaba a leer el build interno nuevo `b=5902`, así que el CSS actualizado del sidebar podía no cargarse.

Este riesgo ya estaba documentado en:
- `docs/bitacora/2026-09-17-1448-chatgpt.md`
- `docs/bitacora/2026-09-17-1450-chatgpt.md`

La regla operativa del repo también indica que una publicación debe coordinar `APP_VERSION` + `version.json`.

## Rama

`chatgpt/sidebar-mobile-cache-fix`

Base:
`main@c64aa0f164b3e06bfa435cf79fe095fde09329e5`

## Corrección

### index.html
`APP_VERSION 58.40 -> 58.41`

Esto cambia la URL pública del loader y obliga a Safari/CDN a pedir una copia nueva.

### version.json
`version 58.40 -> 58.41`

Se agrega changelog explícito:
- barra azul fija con iconos;
- blanco + labels deslizándose por debajo;
- relleno blanco detrás de la curva inferior;
- caché de iPhone/Safari corregida.

### parches-seguros.js
Build interno:
`5902 -> 5903`

Esto fuerza además la descarga fresca de `parches-sidebar-curva.css` y de las demás capas registradas por el loader.

## Importante

No se cambió nuevamente el diseño del sidebar en esta corrección. El objetivo de esta entrega es que el navegador reciba **el diseño ya publicado** en #352, en lugar de seguir usando la versión anterior cacheada.
