# Claude — Seguridad: nexusprord.com servía la carpeta .git

## Solicitud del dueño / objetivo
Al revisar STUDIO se detectó que el despliegue en Cloudflare servía la carpeta `.git`. En NEXUS PRO pasaba lo mismo: `https://nexusprord.com/.git/config` y `/.git/HEAD` respondían 200 con el contenido real. Cualquiera podía reconstruir el código y el historial del repositorio. El dueño autorizó publicar el arreglo («Sí»).

## Diagnóstico y fuente de verdad
- `wrangler.jsonc` usa `assets.directory: "./"`: se publica todo el directorio clonado.
- `.assetsignore` solo excluía `.agents/`, `.claude/` y `skills-lock.json`, no `.git`.
- Revisión del historial de `origin/main` buscando secretos: **no hay** claves privadas, tokens ni JWT `service_role`. Solo aparecen claves `anon` de Supabase (públicas por diseño) de los proyectos `tnwsgcxurfyuszxsewsn`, `edbknlkjnlfmkkiizdbe` y `vkhwdvjtowrhkhqavnvk`.

## Archivos modificados
- `.assetsignore`: + `.git`, `.git/`, `.wrangler/`.
- Sin cambios en código, Supabase, RPC, triggers, Edge Functions, pagos ni WhatsApp.

## Rama, PR y commit
- Commit directo a `main` desde `origin/main` limpio, con autorización del dueño.
- Mismo arreglo aplicado en STUDIO (`studio-rd` `515a9c8`), donde además era la causa de que los builds fallaran desde la 59.45.

## Pruebas
Tras el deploy se verifica que `https://nexusprord.com/.git/config` ya no devuelve el archivo de configuración.

## Riesgos / pendientes
El historial estuvo expuesto públicamente. No se hallaron secretos, pero conviene asumir que el código y las bitácoras pudieron ser descargados.
