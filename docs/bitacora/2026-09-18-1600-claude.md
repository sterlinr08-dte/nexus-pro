# 2026-09-18 16:00 — Claude — Fix real: tema "vidrio" (body.tema-glass) ganaba por especificidad de ID

## Para ChatGPT

El dueño probó correctamente esta vez en la vista previa (confirmé por la URL en su captura) y el
contenido de fondo (tarjetas del dashboard) se transparentaba a través del panel del sidebar. Mi
fix anterior (`082ac08`, apagar `backdrop-filter`) no fue suficiente porque **no era la causa
completa** — encontré la causa real revisando `index.html`:

```css
body.tema-glass .sb,body.tema-glass nav.sb,body.tema-glass #sbEl{
  background:rgba(255,255,255,.5) !important;
  backdrop-filter:blur(20px) saturate(160%);
  ...
}
```

`body.tema-glass #sbEl` usa un selector por **id** (`#sbEl`), especificidad (1,1,1) — le gana a mi
`nav.sb{background:#fff!important}` (especificidad (0,1,1)) aunque ambos tengan `!important`,
porque entre `!important` en conflicto gana la especificidad más alta, no el orden de carga. Esto
es exactamente el mismo tipo de bug que encontramos la semana pasada con `NEXUS_SIDEBAR_V3` (otro
caso de "gana quien tiene mayor especificidad, no quien carga después"), solo que esta vez el
selector ganador es del propio `index.html`, no de un parche.

No sé por qué `tema-glass` está activo en la cuenta/dispositivo del dueño (no lo investigué — no
era necesario para el fix, y no toqué nada relacionado con el sistema de temas), pero el fix debe
funcionar sin importar qué tema tenga activo cualquier cuenta que abra el sidebar.

## Fix

Agregado un override explícito con el mismo selector por id, para igualar o superar la
especificidad y ganar por orden de carga (mi CSS carga después del `<style>` inline de
`index.html`):

```css
body.tema-glass nav#sbEl.sb,
nav#sbEl.sb{
  background:#ffffff !important;
  backdrop-filter:none !important;
  -webkit-backdrop-filter:none !important;
}
```

No toqué `body.tema-premium` (el otro tema condicional, oscuro) — ese es un modo intencional
distinto (oscuro) y no está causando ningún problema reportado; cambiarlo sin que se pida sería
alcance fuera de lo pedido.

Build interno `b=5890 → b=5891`.
