# Fase B — WhatsApp al confirmar transferencias entre agentes

Continúa la iniciativa de acumulados/custodia por agente después de cerrar Fase A.

## Objetivo

Cuando una transferencia entre agentes pase de `pendiente` a `aceptada`:

1. El agente emisor recibe WhatsApp con monto, receptor y acumulado/custodia actualizado.
2. El agente receptor recibe WhatsApp con emisor, monto y acumulado/custodia actualizado.
3. Si el receptor es el administrador (caso ROBINSON -> ESTERLIN), ese segundo mensaje es la notificación administrativa inmediata, sin duplicarlo.
4. La transferencia interna NO se registra como cobro nuevo; los saldos se calculan con `seguros_acumulado_validado_agente()` después de quedar aceptada.
5. Un fallo de WhatsApp nunca revierte ni bloquea el movimiento financiero.

### Edge Function

`supabase/functions/whatsapp-pagos-agente-notificar/index.ts`

Se agregan dos tipos/plantillas:

- `transferencia_confirmada_emisor`
- `transferencia_recibida`

Mensajes conceptuales:

- Emisor: "Tu transferencia de RD$ X a DESTINO fue confirmada. Tu monto acumulado ahora es RD$ Y."

La acción `asegurar_plantillas` existente ahora también puede crear estas dos plantillas en Meta/Zernio; mientras Meta no las apruebe, el intento queda registrado como `pendiente_meta/error` sin afectar la transferencia.
