## Solicitud del dueño

"Como NEXUS PRO tiene la API key de Cloudflare, hazlo por mí": dejar `studiord.net` sirviendo NEXUS PRO
(Worker `nexus-pro`) para el cliente STUDIO, que usa su propia base Supabase.

## Fuente de verdad encontrada

- El secreto `cloudflare_api_token` del Vault de la base madre contiene la **Global API Key** de la cuenta
  Cloudflare del dueño (no un API token). Por eso `Authorization: Bearer` fallaba con "Invalid API Token"; con
  `X-Auth-Email` + `X-Auth-Key` autentica. El nombre del secreto se conserva para no romper referencias.
- Cuenta Cloudflare: `7faa18426a58d75b8d975b1e00a0d6f3`.
- La zona `studiord.net` **ya existía** (creada por el dueño el 21-sep 22:53 UTC): id
  `cb0458a5fa1f37df5a56cb32903724af`, plan Free, estado `pending`, nameservers asignados
  `edward.ns.cloudflare.com` y `kehlani.ns.cloudflare.com`. Namecheap sigue apuntando a
  `dns1/dns2.registrar-servers.com` (`activation_failure_reason: ns_delegated_from_provider`).
- Todas las llamadas se hicieron desde la base madre con `pg_net` (la credencial nunca salió de Supabase). Como
  `pg_net` no tiene PUT, la Edge Function `nx-cf-dominio` (v2, madre) actúa de puente: no guarda secretos, recibe
  la credencial en cabeceras y solo reenvía a `api.cloudflare.com`.

## Cambios realizados en Cloudflare

1. Borrados los registros importados de la página de estacionamiento de Namecheap:
   `A studiord.net → 192.64.119.67` y `CNAME www → parkingpage.namecheap.com`. Se conservaron los 5 MX y el TXT
   SPF de reenvío de correo de Namecheap (`eforward*.registrar-servers.com`).
2. Dominios personalizados del Worker `nexus-pro` (producción), con certificado emitido por Cloudflare:
   - `studiord.net` → id `5d4308eb3c8405c696eda8705693ff6c59d0ad1f`
   - `www.studiord.net` → id `c5b76f072a2b8143a2d942215c59b8db50542c55`
   (`nexusprord.com` sigue igual.)

## Lo que falta (manual, en Namecheap)

Domain List → `studiord.net` → Manage → **Nameservers: Custom DNS** →
`edward.ns.cloudflare.com` y `kehlani.ns.cloudflare.com`. Propagación típica: minutos a pocas horas.
Cuando Cloudflare active la zona, `https://studiord.net` servirá el `main` actual, cuyo mapa por host
(`index.html`, publicado en `a92fdc6`) ya envía ese dominio a la base STUDIO.

## Riesgos y seguridad

- El dueño mostró la Global API Key en una captura dentro del chat. Recomendación: cuando la zona esté activa,
  Cloudflare → Perfil → API Tokens → **Global API Key → Change**, y actualizar el valor en el Vault (mismo nombre).
- Preferible a futuro: un API token con permisos limitados (Zone DNS Edit + Workers Scripts Edit) en vez de la
  clave global.
- `nx-cf-dominio` (v1 en STUDIO, v2 en madre) puede eliminarse cuando termine esta configuración.
