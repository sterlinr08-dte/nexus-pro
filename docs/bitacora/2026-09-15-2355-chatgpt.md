# 2026-09-15 23:55 — ChatGPT — Entrada y Salida en Novedades

## Solicitud del dueño

Agregar dentro del módulo **Novedades** dos acápites operativos: **Entrada** y **Salida**. La sección **Salida** debe seleccionarse automáticamente únicamente cuando un cliente acumule **dos meses vencidos juntos**.

## Implementación publicada

Se actualizó `parches-clientes-novedades.js` para añadir una clasificación operativa derivada de los datos existentes, sin cambiar el estado real del cliente ni crear una baja automática.

### Entrada

Se clasifica como **Entrada** cuando la novedad corresponde a:
- `proceso_actual`, generado desde `clientes.estado_cliente='EN_PROCESO'`; o
- estado `POR_ACTIVAR`.

Esto conserva la señal fiable ya existente para clientes en activación/proceso y no inventa una entrada basándose en número de póliza.

### Salida

Se clasifica como **Salida** cuando:
- la novedad automática `mora_fifo` contiene `metadata.meses >= 2`; o
- existe una novedad manual ya escalada a `POR_RETIRAR`.

Con **un solo mes vencido**, el cliente puede seguir apareciendo como `EN_RIESGO`, pero **no aparece en Salida** y el botón para marcarlo `POR_RETIRAR` no se habilita desde esa novedad.

La clasificación usa la metadata FIFO que ya actualiza `novedades_sync_automaticas_core()`, por lo que no fue necesario agregar una nueva columna ni una migración. Al abrir Novedades se ejecuta la sincronización existente y el filtro refleja el número real de períodos pendientes.

## Regla de seguridad de negocio

**Dos meses vencidos habilitan el caso como candidato de Salida, pero no dan de baja al cliente automáticamente.** La salida definitiva sigue requiriendo decisión/confirmación humana. La acción `Marcar por retirar` solo aparece para un caso que ya cumple la condición de Salida.
