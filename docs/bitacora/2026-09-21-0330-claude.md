# Pago validado — notificación con desglose por ciclo + aviso al administrador

**Fecha:** 2026-09-21
**Autor:** Claude

## Solicitud

El dueño pidió que al validar un pago:

1. El agente reciba WhatsApp con dos valores separados: **cobrado en este ciclo** y **acumulado de ciclos anteriores**.
2. El administrador **también** reciba la misma información sobre ese agente.

Antes solo se enviaba al agente un único valor de acumulado total (all-time), y el administrador no recibía nada.

## Plantillas nuevas sometidas a Meta

### `pago_validado_agente_ciclo` (para el agente)

```
Hola {{1}}. Se validó un pago de RD$ {{2}} del cliente {{3}} en NEXUS PRO.
Cobrado en este ciclo: RD$ {{4}}.
Acumulado de ciclos anteriores: RD$ {{5}}.
Consulta el detalle en el sistema.
```

Variables: nombre agente, monto pago, nombre cliente, cobrado ciclo actual, saldo inicial (anterior).

### `pago_validado_admin_ciclo` (para el administrador)

```
Hola {{1}}. El agente {{2}} validó un pago de RD$ {{3}} del cliente {{4}} en NEXUS PRO.
Cobrado por el agente este ciclo: RD$ {{5}}.
Acumulado de ciclos anteriores: RD$ {{6}}.
Consulta en el sistema.
```

Variables: nombre admin, nombre agente, monto pago, nombre cliente, cobrado ciclo actual, saldo inicial (anterior).

**Estado:** ambas PENDING en Meta (sometidas vía `asegurar_plantillas` de la Edge Function).

## Fuente de los datos de ciclo

El trigger usa `seguros_resumen_ciclo_agente_core(agente_id, periodo)` que devuelve:

- `cobrado_validado` → cobrado en el ciclo actual (lo que el dueño llama "acumulado por ciclo").
- `saldo_inicial` → dinero en custodia al inicio del ciclo (lo que el dueño llama "acumulado de ciclos anteriores").

El periodo vigente se determina por la regla 20→20 en zona `America/Santo_Domingo`.

## Lógica del trigger actualizado

`trg_whatsapp_pago_validado()` ahora:

1. Calcula el periodo vigente (día ≥ 20 → mes actual; día < 20 → mes anterior).
2. Llama a `seguros_resumen_ciclo_agente_core` para obtener `cobrado_validado` y `saldo_inicial`.
3. Envía `pago_validado_agente_ciclo` al agente cobrador.
4. Envía `pago_validado_admin_ciclo` a cada administrador activo que NO sea el propio agente cobrador.
5. Si falla el cálculo de ciclo, hace fallback a la plantilla anterior (`pago_validado_resumen`).

La notificación al cliente (`pago_aplicado`) no se tocó.
