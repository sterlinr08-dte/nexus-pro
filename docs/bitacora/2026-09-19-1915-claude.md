## Causa raíz

`nav#sbEl.sb .ni-l` (móvil) y `.sb:not(.col) .ni-l` (desktop) no tenían `min-width:0` ni
`overflow`/`text-overflow` propios. Con `flex:0 0 auto` (móvil, antes del fix) o el `flex-shrink:1`
por defecto pero `min-width:auto` (desktop), el texto largo desbordaba la fila y
`nav.sb .ni{overflow:hidden}` (regla base de `index.html`, nunca tocada) lo cortaba a la mitad sin
avisar. En móvil además el estado activo (`.ni.on .ni-l`) tenía `max-width:none` explícito, así que
ni siquiera respetaba el límite que sí tenía el estado inactivo.

Primer intento de fix usó `display:inline-flex` + `text-overflow:ellipsis` — seguía cortando sin
"…". Causa: `text-overflow` no se aplica dentro de un contenedor `flex`/`inline-flex` (limitación
real de CSS, no bug de esta implementación). Cambié `.ni-l` a `display:inline-block` (sigue
funcionando como flex-item de `.ni` porque el outer display se "blockifica" igual) y ahí sí
funcionó — confirmado con la segunda captura.

## Cambios

`parches-sidebar-curva.css`:
- Móvil: `.ni-l` (base y `.on`) ahora `inline-block`, `flex:0 1 auto`, `min-width:0`,
  `max-width:100%`, `overflow:hidden`, `text-overflow:ellipsis`. Se quitó el `max-width:calc(100% -
  var(--nx-rail) - 28px)` (estaba mal calculado, dejaba ~86px reales para el texto). Badge/chevron/
  pill ADMIN reciben `flex-shrink:0` explícito (`.ni > *:not(.ni-l)`) para que solo el texto ceda
  espacio, nunca ellos.
- Desktop: mismo criterio (`min-width:0; max-width:100%; overflow:hidden; text-overflow:ellipsis`)
  agregado a `.sb:not(.col) .ni-l` — este bug también existía en desktop (nadie lo había reportado,
  lo encontré al verificar ahí también), sin tocar el mecanismo del indicador `spring-ind`/`fitWidth`
  que sigue igual.

`index.html`: `nxSidebarSpringSync()` ahora sale de inmediato si `#springInd` está `display:none`
(caso móvil desde el fix de las 18:34) — antes seguía midiendo/animando un elemento invisible en
cada `nav()`. Detalle de eficiencia, no cambia nada visual.

Build interno `b=5911 → b=5912`, `APP_VERSION` `58.49 → 58.50`, entrada en `version.json`.
