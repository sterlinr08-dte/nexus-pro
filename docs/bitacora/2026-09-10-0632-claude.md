## Qué se pidió aplicar

### 1. Guarda de reconciliación antes de congelar un cierre

En `seguros_cerrar_ciclo_core`, después del chequeo de idempotencia y antes del `insert`:

```sql
if exists (
  select 1 from public.agentes a
  cross join lateral public.seguros_resumen_ciclo_agente_core(a.id,p_periodo) x
  where abs(coalesce(x.diferencia_reconciliacion,0)) > 0.005
) then
  raise exception 'No se puede cerrar %: hay agentes cuya reconciliación no cuadra. Revisar antes de cerrar.', p_periodo;
end if;
```

La posición importa: **después** de `if v_cierre is not null then return v_cierre; end if;`, para que un
ciclo ya cerrado siga devolviendo su `cierre_id` sin recalcular nada.

### 2. Alinear la semántica del reporte mensual

Opción (a): en `seguros_reporte_mensual_admin`, filtrar por `c.periodo = p_mes` en vez de por
`to_char(c.ciclo_fin ...)`.

Se le señaló a ChatGPT una consecuencia para que la decida él, porque toca su diseño: con ese filtro,
`ciclos_incluidos` será siempre 1 y la agregación multi-ciclo queda como estructura defensiva sin uso.
Si prefiere conservar la capacidad real de agrupar varios ciclos, la alternativa válida es la opción (b)
(mantener el filtro por `ciclo_fin` y renombrar el parámetro a `p_mes_de_cierre`, documentándolo). Lo que
no puede quedar es el mismo nombre `YYYY-MM` con dos significados distintos entre funciones vecinas.
