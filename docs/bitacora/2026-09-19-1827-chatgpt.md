# Corrección efectiva — selector móvil forzado al ancho real del texto

## Contexto

El dueño volvió a confirmar con captura real de iPhone que el selector activo seguía viéndose largo, incluso después de las publicaciones 58.46 y 58.47.

La captura muestra que el rectángulo activo aún ocupa gran parte de la fila aunque el spring indicator ya estaba oculto.

## Diagnóstico

El selector móvil actual se dibujaba con `.ni-l::before`, pero la etiqueta `.ni-l` podía conservar un ancho mayor al contenido debido a la cascada/flex del sidebar.

Por eso, aunque la píldora estaba técnicamente atada al label, seguía heredando un ancho visual demasiado grande.

## Rama

`chatgpt/mobile-selector-shrinkwrap-fix`

Base:
`main@e1e8773ebb1eb7bfbc87cc72357512825b8b6869`

## Corrección

En móvil:

```css
nav#sbEl.sb .ni-l{
  display:inline-flex !important;
  flex:0 0 auto !important;
  width:max-content !important;
  inline-size:max-content !important;
  max-width:calc(100% - var(--nx-rail) - 28px) !important;
}
```

Además se refuerza el mismo shrink-wrap para:
- `body.spring-nav`
- `body.tema-premium`
- `body.tema-glass`

La píldora activa ahora queda:
- 10px antes del texto;
- 10px después del texto;
- sin usar el ancho restante de la fila.
