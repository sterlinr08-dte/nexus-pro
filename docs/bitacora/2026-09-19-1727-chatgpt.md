# Corrección inmediata — selector activo móvil seguía ancho

## Reporte del dueño

Después de publicar el ajuste del selector activo, el dueño mostró una captura real en iPhone y confirmó: **"Sigue igual"**.

## Diagnóstico confirmado

La publicación anterior sí ajustaba el selector en desktop, pero el JS tenía este guard:

`window.innerWidth <= 768`

Ese guard desactivaba deliberadamente el cálculo dinámico en móvil. Además, el CSS móvil mantenía:

`right:12px`

por lo que el selector seguía ocupando casi todo el panel blanco.

La captura confirmó exactamente ese caso: **DASHBOARD** mantenía una píldora demasiado larga a la derecha.

## Rama

`chatgpt/mobile-active-selector-fit-fix`

Base:
`main@a22566def22742f9880d4668a139af20023f193c`

## Corrección

### CSS móvil

El selector activo ahora usa:
- `right:auto`;
- ancho fallback compacto de `104px`;
- transición suave del ancho.

Cuando el JS mide el contenido, ese ancho se reemplaza por el ancho real necesario.

### JS del resorte

`fitWidth(el)` ahora también funciona en móvil **cuando el drawer está abierto**.

Reglas:
- móvil cerrado: no calcula ancho;
- móvil abierto: calcula según texto + badge;
- desktop colapsado: conserva comportamiento anterior;
- desktop expandido: sigue usando cálculo dinámico.

El selector termina aproximadamente 14px después de la etiqueta o badge.
